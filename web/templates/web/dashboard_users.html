Users

Three roles sharing a single detection surface.

This page sketches how users and roles might be expressed in the interface. Everything here is simulated: the focus is on language, rhythm, and layout.

Role

Owner

Owns the system: rules, users, and environments. Decides what the detection surface should feel like and where it is allowed to make noise.

Scope: rules catalogue · environments · user management.

Role

Analyst

Lives inside alerts and endpoints. Investigates, triages, and tunes rules, but does not change the overall system framing.

Scope: alerts · endpoints · investigations · rule feedback.

Role

Read-only

Follows the story without changing it. Can see the same surface and language, but cannot edit anything underneath.

Scope: dashboards · reports · read-only exports.

How roles and UI relate

Visual roles first, permission model later.

  • The role pills in the topbar and the table rows here are purely visual in this phase – no real permissions are enforced yet.
  • In a live system, each user would come from your identity provider, with roles mapped to groups or claims.
  • The aim is to keep the language stable so that wiring real auth later does not require a redesign.
  • This page can grow into a full "People & access" section without changing its core layout.
